# External anchor of the first real BotVow chain head

This folder is an external witness for the head of the first real BotVow chain. It uses RFC 3161 timestamps only. There is no blockchain and no OpenTimestamps.

The timestamp authorities sign the SHA-256 of `2026-11-19-bv-6359d810078e-anchor.txt`. That file states the chain id and the head hash. Only the hash of the file is sent to the TSA, not the file itself.

## Identifiers

| Field | Value |
|---|---|
| Spec | `botvow/0.1` |
| Chain id | `bv-6359d810078e` |
| Head (SHA-256 of the seal, seq 3) | `205bc1897e1e7ad30012aab5915a84b82397f3114ac368cdabafb52ddddbac87` |
| Record time (in the chain) | `2026-11-14T14:05:32Z` |
| SHA-256 of the anchor file | `5255a19b0215422489af3e5c1716529bb932c307fe957eb04792cc773dccfae1` |

The head is the `entry_hash` of the last entry (`type: seal`) of the signed chain. Anyone with `registo.json` can check it with:

```bash
python3 tools/botvow.py verify registo.json --head 205bc1897e1e7ad30012aab5915a84b82397f3114ac368cdabafb52ddddbac87
```

That command should print `VERIFY OK`.

## Timestamps (RFC 3161, SHA-256)

The same timestamp query (`2026-11-19-bv-6359d810078e.tsq`) was sent to two independent public TSAs:

| TSA | Endpoint | Time (UTC) | Reply file |
|---|---|---|---|
| [FreeTSA](https://freetsa.org/) | `https://freetsa.org/tsr` | 2026-11-19 21:57:23 UTC | `2026-11-19-bv-6359d810078e-freetsa.tsr` |
| [DFN-Verein](https://www.dfn.de/) (Zeitstempel, "PN: Zeitstempel 2026") | `https://zeitstempel.dfn.de` | 2026-11-19 21:58:10 UTC | `2026-11-19-bv-6359d810078e-dfn.tsr` |

DigiCert (`http://timestamp.digicert.com`) was also tried as a second TSA. It returned HTTP 500 on every attempt, so it was not used. DFN-Verein was used instead.

## How to verify with OpenSSL

From this `anchors/` directory:

```bash
# 1. The query must be a SHA-256 of the anchor file
openssl ts -query -in 2026-11-19-bv-6359d810078e.tsq -text
# Message data should be 5255a19b… (the SHA-256 of the anchor file)

# 2. FreeTSA
openssl ts -verify \
  -data 2026-11-19-bv-6359d810078e-anchor.txt \
  -in 2026-11-19-bv-6359d810078e-freetsa.tsr \
  -CAfile freetsa-cacert.pem \
  -untrusted freetsa-tsa.crt
# Expected: Verification: OK
# A warning that freetsa-tsa.crt is not a CA certificate is expected
# (it is the TSA end-entity certificate).

# 3. DFN-Verein
openssl ts -verify \
  -data 2026-11-19-bv-6359d810078e-anchor.txt \
  -in 2026-11-19-bv-6359d810078e-dfn.tsr \
  -CAfile dfn-community-root-ca-2022.pem \
  -untrusted dfn-community-issuing-ca-2022.pem
# Expected: Verification: OK
```

You can also verify against the original query file instead of `-data`, by replacing that option with `-queryfile 2026-11-19-bv-6359d810078e.tsq`.

To read the time stored in a reply:

```bash
openssl ts -reply -in 2026-11-19-bv-6359d810078e-freetsa.tsr -text
openssl ts -reply -in 2026-11-19-bv-6359d810078e-dfn.tsr -text
```

## What this does and does not prove

A valid RFC 3161 reply proves that the SHA-256 of the anchor file existed at the stated UTC time, according to that TSA. Together with a `VERIFY OK` check of the chain against the published head, that is an independent public record of the head. It does not replace the BotVow signatures, and it is not a qualified electronic timestamp under eIDAS.
